# N2–N8 software review and acceptance

Hardware has not been tested. All MIDI semantics and firmware assumptions retain
those qualifications in MIDI_PROTOCOL.md and TODO.md.

## N2 — frontend contract review

Reviewed pendingPreset, mcpPort, realignLayer, resetParameters, configuration edits
and preset replacement, ParameterWorkspace, WorkspaceTabsView and external service
settings. Fixed direct ConsoleModel access in the workspace: connection drafts,
port/profile application and monitor clearing now cross PanelSnapshot/PanelIntents.
Endpoint presentation types no longer live in the CoreMIDI transport file.

The parameter editor initializes from the applied configuration, removes the duplicate
neutral preset button, and shows live controls only for applied parameters with known
values, using the applied range rather than an uncommitted draft range. This prevents
sending invalid values while editing limits and avoids displaying draft defaults as
observations. Applied configuration edits preserve values; preset replacement and
reset remain separate explicit actions. MCP shows the actual configured port.

Validation: deterministic adapter regression, full Swift tests, Swift build,
SwiftFormat/Ruff. Mouse acceptance is tracked separately under N5.

## N3 — model-owned preset confirmation

confirmLoadPreset takes no arguments. The model uses its own pendingPreset and
ignores stale/repeated confirmations. Successful configuration edits dismiss an
obsolete pending replacement. Immediate preset loads use a private replacement
method. Review checked cancellation, repeated action, configuration edits while a
confirmation is pending, defaults and motor suppression.

Validation: new deterministic stale-confirmation tests, existing preset/import
regressions, full Swift tests/build, SwiftFormat/Ruff.

## N4 — build and toolchain review

Reviewed all project-owned configs/*.py, tools/*.py, hook, FreeCM manifest and
packaging flow. Vendored FreeCM files remain unmodified and retain their license.
Fixed generated-write paths traversing symlinked build ancestors, including setup
markers and package checksums. Cleanup intentionally unlinks child symlinks without
following them. Bundle validation now accepts SwiftPM's lowercase language folders
and still rejects missing languages. Smoke validation parses a complete JSON marker
and requires a Boolean false; coincidental substrings cannot pass. DMG packaging
uses only the app bundle, avoiding unrelated files in its parent directory. MCP
integration checks now use explicit validation rather than optimization-removable
assertions, and importing the helper no longer starts network activity.

Review also checked subprocess argument arrays (no shell evaluation), version
validation, environment restoration, command failure propagation, hook opt-in,
ad-hoc signature verification and checksum generation. Preview capture diagnosis
and its subprocess lifecycle are handled in N6.

Validation: workflow unit tests (including new symlink, smoke-marker and lowercase
bundle regressions), manifest validation, full Swift tests/build, formatting and
local native ZIP/DMG packaging with signature verification and startup smoke.
These are local ad-hoc artifacts, without notarization or hardware validation.

See NATIVE_ACCEPTANCE.md. Native UI access failed before a usable window could be

## N6 — isolated preview lifecycle and timeout diagnostics

The old command succeeds locally. Historical hosted failure 42998697476 timed out
without reaching a completion marker; a same-revision remote reproduction was
requested in run 43005877417. A window .task is an unsuitable command entry because
it requires window appearance before any diagnostics can execute. The snapshot
command now starts its own isolated AppKit launch delegate, independent of the
interactive SwiftUI window lifecycle, and requires --integration-test.

The helper writes per-scene launch/layout/cache logs, samples the owned process on
timeout, kills and reaps it, deletes stale images and validates fresh PNG headers.
Manual CI retains these diagnostics even when capture fails. All views are still
rendered through app-owned offscreen hosting; no desktop capture or hardware access.

Validation so far: full Swift tests/build, 12 workflow tests, formatting, local
five-scene/language capture (including visual inspection of the English console).
Hosted diagnosis remains pending until the manual run completes; do not treat a
local pass as proof of the historical remote cause.
