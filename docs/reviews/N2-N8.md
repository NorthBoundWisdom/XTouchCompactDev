# N2–N8 software review and acceptance

Hardware has not been tested. All MIDI semantics and firmware assumptions retain
those qualifications in MIDI_PROTOCOL.md and TODO.md.

## N2 — frontend contract review

Reviewed pendingPreset, mcpPort, realignLayer, resetParameters, configuration edits
and preset replacement, ParameterWorkspace, WorkspaceTabsView and external service
settings. Fixed direct ConsoleModel access in the workspace: connection drafts,
port/profile application and monitor clearing now cross PanelSnapshot/PanelIntents.
Endpoint presentation types no longer live in the CoreMIDI transport file.

The parameter editor initializes from the applied configuration, removes the duplicate
neutral preset button, and shows live controls only for applied parameters with known
values, using the applied range rather than an uncommitted draft range. This prevents
sending invalid values while editing limits and avoids displaying draft defaults as
observations. Applied configuration edits preserve values; preset replacement and
reset remain separate explicit actions. MCP shows the actual configured port.

Validation: deterministic adapter regression, full Swift tests, Swift build,
SwiftFormat/Ruff. Mouse acceptance is tracked separately under N5.

## N3 — model-owned preset confirmation

confirmLoadPreset takes no arguments. The model uses its own pendingPreset and
ignores stale/repeated confirmations. Successful configuration edits dismiss an
obsolete pending replacement. Immediate preset loads use a private replacement
method. Review checked cancellation, repeated action, configuration edits while a
confirmation is pending, defaults and motor suppression.

Validation: new deterministic stale-confirmation tests, existing preset/import
regressions, full Swift tests/build, SwiftFormat/Ruff.
